# Мониторинг и наблюдаемость

## Обзор

Данный документ описывает подход к мониторингу системы автоматической обработки тикетов поддержки на этапе PoC и в production-среде.

## Метрики приложения

### Бизнес-метрики

| Метрика | Описание | Целевое значение |
|---------|----------|------------------|
| `auto_close_rate` | Доля тикетов, закрытых автоматически | 30–50% |
| `escalation_rate` | Доля тикетов, эскалированных оператору | < 30% |
| `suggest_rate` | Доля тикетов с предложенным черновиком | остаток |
| `pii_detected_rate` | Доля тикетов с обнаруженными ПДн | мониторинг |
| `avg_response_time_ms` | Среднее время обработки одного тикета | < 500 мс |

### Технические метрики

| Метрика | Описание |
|---------|----------|
| `classifier_confidence_mean` | Средняя уверенность классификатора |
| `retrieval_top1_score_mean` | Средний score первого результата поиска |
| `llm_fallback_count` | Количество обращений к заглушке LLM |
| `pipeline_error_count` | Количество ошибок в пайплайне |
| `degradation_level` | Текущий уровень деградации (0/1/2/3) |

## Логирование

Каждый обработанный тикет записывается в JSONL-лог (`logs/audit.jsonl`) со следующими полями:

```json
{
  "ticket_id": "T-001",
  "timestamp": "2024-01-15T10:30:00Z",
  "topic": "billing",
  "confidence": 0.87,
  "pii_level": "low",
  "retrieval_score": 0.82,
  "decision": "suggest",
  "degradation_level": 0,
  "processing_time_ms": 145
}
```

### Уровни логирования

- **INFO** — нормальная обработка тикета, решение принято
- **WARNING** — уверенность ниже порога, обнаружены ПДн высокого риска
- **ERROR** — ошибка в компоненте пайплайна, активирован fallback
- **CRITICAL** — полный отказ системы, все тикеты направлены операторам

## Алерты

### Критические алерты (немедленная реакция)

- `auto_close_rate` упал ниже 10% за последние 100 тикетов
- `pipeline_error_count` > 5 за 5 минут
- `degradation_level` = 3 (полная деградация)
- Время ответа API > 5 секунд

### Предупредительные алерты

- `classifier_confidence_mean` < 0.5 за последние 50 тикетов (дрейф данных)
- `pii_detected_rate` > 50% (аномалия в входящем потоке)
- `escalation_rate` > 60% (перегрузка операторов)

## Дашборд (production)

В production-среде рекомендуется использовать Grafana + Prometheus со следующими панелями:

1. **Обзор системы** — текущий уровень деградации, статус компонентов
2. **Распределение решений** — соотношение auto_close / suggest / escalate
3. **Качество ML** — уверенность классификатора, score поиска (тренды)
4. **ПДн риски** — распределение уровней риска по тикетам
5. **Производительность** — latency percentiles (p50, p95, p99)
6. **Ошибки** — error rate, типы ошибок

## Мониторинг дрейфа данных

Для production-системы необходимо отслеживать:

- **Дрейф входных данных** — изменение распределения тем тикетов
- **Дрейф предсказаний** — изменение распределения решений классификатора
- **Качество ответов** — обратная связь от операторов по качеству предложенных черновиков

Рекомендуемые инструменты: Evidently AI, MLflow, Prometheus + Grafana.

## PoC vs Production

| Аспект | PoC | Production |
|--------|-----|------------|
| Логи | JSONL-файл | Elasticsearch / Loki |
| Метрики | Stdout | Prometheus + Grafana |
| Алерты | Нет | PagerDuty / Telegram |
| Трейсинг | Нет | Jaeger / OpenTelemetry |
| Дашборд | Нет | Grafana |
