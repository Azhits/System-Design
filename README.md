# System Design: Автоматизация обработки тикетов поддержки

Доказательство концепции (PoC) и системный дизайн для автоматической системы сортировки и подготовки ответов на тикеты поддержки. Система классифицирует входящие тикеты, определяет риск наличия персональных данных (ПДн), ищет релевантные ответы в базе знаний и принимает решение — автоматически закрыть тикет, предложить черновик оператору или эскалировать на полную ручную проверку — с поддержкой плавной деградации при высокой нагрузке или недоступности LLM.

```
│   ├── monitoring.md      # Метрики, алерты, журнал аудита

    ├── classifier.py      # Классификация темы + оценка уверенности
    ├── retrieval.py       # TF-IDF поиск по базе знаний (cosine similarity)

    ├── degradation.py     # Логика уровней деградации (L0–L4)

    │   └── .gitkeep
    └── static/

```

## Быстрый старт

```bash
# 1. Установить зависимости
pip install -r requirements.txt

# 2. Запустить демо
python poc/run_demo.py

# 3. Открыть в браузере
# http://127.0.0.1:8000
```

Также можно использовать curl для отправки тикетов и просмотра журнала аудита.

## Логика принятия решений

1. **Классификация** — определение темы тикета и уверенности модели
2. **Проверка ПДн** — анализ текста на наличие персональных данных и уровень риска
3. **Поиск** — нахождение релевантных статей базы знаний через TF-IDF
4. **Решение:**
   - **Высокий риск ПДн** — только retrieval-черновик, всегда эскалация
   - **Рискованная тема** (billing, complaint, abuse) — обязательная проверка оператором
   - **Высокая уверенность + безопасно** — автоматическое закрытие или предложение черновика
   - **Иначе** — эскалация оператору
5. **Деградация** — ошибки LLM активируют fallback на retrieval-шаблоны
6. **Логирование** — все решения записываются в `logs/audit.jsonl`

## Технологический стек

| Компонент | Технология |
|-----------|------------|
| API-сервер | FastAPI + Uvicorn |
| Классификация | scikit-learn (TF-IDF + Decision Tree) |
| Поиск | TF-IDF cosine similarity |
| Детектор ПДн | Regex-паттерны |
| LLM | Mock-заглушка (production: OpenAI / внутренний LLM) |
| Шаблоны | Jinja2 |
| Логирование | JSONL-файл (`logs/audit.jsonl`) |

## Замечание

Это PoC: LLM-клиент является заглушкой, поиск реализован через TF-IDF, детектор ПДн основан на регулярных выражениях. Подробная production-архитектура и обоснование решений — в папке `docs/`.
